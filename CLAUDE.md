## Project Overview

Yogee is a Flutter cross-platform app (Android, iOS, Web) for music streaming and wellness — featuring meditation audio, playlists, community posts, journaling, and courses. The UI is largely generated by FlutterFlow; custom logic lives in `lib/custom_code/`.

## Commands

### Flutter (frontend)
```bash
flutter pub get          # Install dependencies
flutter analyze          # Run Dart static analysis
flutter test             # Run widget tests
flutter run              # Run app in development
flutter build apk        # Build Android APK
flutter build ios        # Build iOS
flutter build web        # Build web
flutter test test/widget_test.dart  # Run a single test file
```

### Firebase Cloud Functions (backend)
```bash
cd firebase/functions
npm install
npm run lint             # ESLint (zero warnings allowed)
npm run serve            # Run functions emulator locally
npm run compile          # Compile TypeScript
npm run logs             # Stream function logs
```

## Architecture

### State Management
`lib/app_state.dart` holds `FFAppState`, a singleton `ChangeNotifier` registered with Provider at the root. It stores global playback state (current song, player visibility, queue), navigation state, and user-level selections. Persisted fields use `shared_preferences`.

### Backend / Firestore Schema
`lib/backend/schema/` contains auto-generated Dart record classes mirroring Firestore collections: `users`, `songs`, `albums`, `playlists`, `artists`, `posts`, `comments`, `chats`, `chat_messages`, `notifications`, `downloads`, `written_note`. Each record class handles serialization, deserialization, and Firestore stream queries.

### Authentication
`lib/auth/` provides a multi-provider auth system (Email, Google, Apple, GitHub, JWT, Anonymous) built on Firebase Auth. `auth_util.dart` exposes the current user and auth stream. Auth state flows reactively through the app via `BaseAuthUser`.

### Navigation
GoRouter (`go_router`) handles declarative routing. Route definitions live in `lib/flutter_flow/nav/`. The bottom nav component (`lib/components/nav_bottom_widget.dart`) drives tab-level navigation.

### Custom Code vs. FlutterFlow Code
- `lib/flutter_flow/` — auto-generated utilities, theme, and components. Avoid manual edits; they may be overwritten by FlutterFlow exports.
- `lib/custom_code/actions/` — hand-written action handlers invoked by the FlutterFlow runtime. Audio playback (play, pause, skip, seek) and chat/notification helpers live here. This is the primary place to add business logic.
- `lib/pages/`, `lib/community/`, `lib/meditation/`, `lib/journal/`, `lib/settings/` — feature page widgets, mix of generated and custom code.

### Audio Playback
Audio control actions in `lib/custom_code/actions/` (`init_audio_player.dart`, `play_song.dart`, `pause_song_btn.dart`, `skip_to_next.dart`, `seek_forward.dart`, `seek_backward.dart`) orchestrate `just_audio` and `audio_service`. Player UI state is kept in `FFAppState`.

### Cloud Functions Backend
`firebase/functions/` runs on Node.js 20. `index.js` exports callable and HTTP functions. `api_manager.js` handles third-party HTTP integrations. Key integrations: Stripe / Braintree / Razorpay (payments), Mux (video streaming), OneSignal (push notifications), LangChain with OpenAI / Google GenAI / Anthropic (AI features).

### Firebase Security
`firebase/firestore.rules` — most collections allow read/write but no delete; users collection is creator-restricted with open read; artists collection is read/create only. `firebase/storage.rules` governs media uploads.
