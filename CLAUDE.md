## Project Overview

Yogee is a Flutter cross-platform app (Android, iOS, Web) for music streaming and wellness — featuring meditation audio, playlists, community posts, journaling, and courses.

The UI was originally generated by FlutterFlow, but **this repository is now the source of truth** — all 49 commits are hand-authored, there is no FlutterFlow bot commit, no `flutterflow` branch, and generated page files carry hand-written comments and fixes. Edit them directly. If anyone ever re-exports from FlutterFlow, see "Generated vs. hand-written" below for what would be lost.

## Environment requirements

These are not suggestions — the build fails without them.

| Requirement | Why |
|---|---|
| **Flutter 3.41.7** (Dart 3.11.5) | Its `flutter_localizations` pins `intl` to **exactly 0.20.2**, which is what `pubspec.yaml` requires. Newer Flutter needs `intl ^0.20.3` and `flutter pub get` fails with "version solving failed". |
| **JDK 21** | Android Studio bundles JetBrains Runtime 25; Gradle 8.12 supports ≤23 and fails with `Error resolving plugin [dev.flutter.flutter-plugin-loader] > 25.0.2`. Point Flutter at it: `flutter config --jdk-dir "<path-to-jdk-21>"`. |
| **Java 21+ on PATH** | `firebase-tools` refuses older Java, invokes the bare command `java`, and ignores `JAVA_HOME`. `firebase/emulators.cmd` works around this per-process. |

On Windows, if Gradle fails with `PKIX path building failed`, add `systemProp.javax.net.ssl.trustStoreType=Windows-ROOT` to `%USERPROFILE%\.gradle\gradle.properties`. Keep it at user level — putting it in `android/gradle.properties` breaks macOS and Linux teammates.

`seed.mjs` refuses to run unless `FIRESTORE_EMULATOR_HOST` is loopback and something is listening on it. Do not weaken that guard — without it, a stopped emulator makes the Admin SDK silently fall through to real Firebase.

## Firebase projects — read before running anything

Three projects exist. **On Android the platform files decide which one you hit, not the dart-defines.**

| Project | Reached by | Notes |
|---|---|---|
| `yoogeeapp` | **release** builds (`android/app/google-services.json`) | **Staging / test.** Owner states (2026-08-20) this is not a live end-user project, despite the name and the `release` build type. Its rules are still wide open and `allow delete: if false`, so writes are permanent — but they are not end-user data. |
| `yogee-e62e2` | **debug** builds (`android/app/src/debug/google-services.json`) | Dev project, safe to write to |
| `demo-yoogee` | `--dart-define=USE_FIREBASE_EMULATOR=true` | Local emulator, wiped on restart |

`USE_DEV_FIREBASE` only affects web; on Android the Gradle plugin bakes in whichever `google-services.json` matches the build type.

To verify what an APK actually points at, grep the binary for the project id rather than guessing.

## Architecture

### State Management
`lib/app_state.dart` holds `FFAppState`, a singleton `ChangeNotifier` registered with Provider at the root. It stores global playback state (current song, player visibility, queue), navigation state, and user-level selections. Persisted fields use `shared_preferences`.

### Backend / Firestore Schema
`lib/backend/schema/` contains auto-generated Dart record classes mirroring Firestore collections: `users`, `songs`, `albums`, `playlists`, `artists`, `posts`, `comments`, `chats`, `chat_messages`, `notifications`, `downloads`, `written_note`. Each record class handles serialization, deserialization, and Firestore stream queries.

Composite indexes live in `firebase/firestore.indexes.json`. Any new `where` + `orderBy` combination needs an entry there or the stream fails with `FAILED_PRECONDITION`.

### Authentication
`lib/auth/` provides a multi-provider auth system (Email, Google, Apple, GitHub, JWT, Anonymous) built on Firebase Auth. `auth_util.dart` exposes the current user and auth stream. Auth state flows reactively through the app via `BaseAuthUser`.

Note: `authenticatedUserStream` is a **broadcast** stream, so it does not replay to late listeners. `currentUserDocument` is null on the first build, and `currentUserDocument!` will throw. Guard it.

### Navigation
GoRouter (`go_router`) handles declarative routing. Route definitions live in `lib/flutter_flow/nav/`. The bottom nav component (`lib/components/nav_bottom_widget.dart`) drives tab-level navigation.

### Audio Playback
Audio control actions in `lib/custom_code/actions/` (`init_audio_player.dart`, `play_song.dart`, `pause_song_btn.dart`, `skip_to_next.dart`, `seek_forward.dart`, `seek_backward.dart`) orchestrate `just_audio` and `audio_service`. The player UI is `lib/meditation/audioplayer/audioplayer_widget.dart`, shown as a modal bottom sheet; the seek bar and timer live in `lib/custom_code/widgets/music_player_widget.dart`. Player state is kept in `FFAppState`.

### Cloud Functions Backend
`firebase/functions/` runs on Node.js 20. `index.js` exports callable and HTTP functions, plus `onPostDeleted`, which cascades comment deletion with admin privileges. `api_manager.js` handles third-party HTTP integrations.

## Generated vs. hand-written code

| Path | Status |
|---|---|
| `lib/flutter_flow/` | Generated utilities, theme, components. Avoid manual edits. |
| `lib/backend/schema/*_record.dart` | Generated from the FlutterFlow schema editor. **Add fields there, not here.** |
| `pubspec.yaml` | Generated, including the app `version:` line. Hand-added dependencies would be lost on re-export. |
| `lib/pages/`, `lib/community/`, `lib/meditation/`, `lib/journal/`, `lib/settings/` | Generated page widgets, now edited by hand. |
| `lib/custom_code/actions/`, `lib/custom_code/widgets/` | Hand-written, but both carry an `index.dart` barrel that FlutterFlow regenerates. |
| `lib/custom_code/*.dart` (files at the root) | Hand-written and untouched by any export. **Safest place for shared helpers** — e.g. `card_stroke.dart`, `audio_manager.dart`. |

Generated page widgets are deeply nested with very long `build()` methods (`dashboard_widget.dart` is ~1,400 lines). That is expected; a visual builder never extracts a widget.

## Security constraints — treat production as read-only

- `firebase/firestore.rules` currently grants `allow read: if true` and `allow write: if true` on most collections. Anyone with the public API key can read and write production data. Verified by unauthenticated REST call.
- `allow delete: if false` on every collection except `posts`. **Anything written to production is permanent and no client can remove it.**
- `yoogeeapp` is staging/test per the owner, so writing to it is acceptable for
  testing. Two things still hold: `allow delete: if false` means anything
  written there is permanent, and it is the project a shipped release build
  points at — so treat it as shared, not scratch.
- Never commit a service-account key, `android/key.properties`, or a `.jks`. All are gitignored. Pass key paths via `GOOGLE_APPLICATION_CREDENTIALS`, never paste contents.
- The Firebase API keys in `google-services.json` / `GoogleService-Info.plist` are client identifiers that ship in every binary — not secrets, and not worth rotating. The wide-open rules are the actual exposure.
